## 이 설계가 8장과 다른 점 — 채널이 뒤바뀐다

```text
8장 (axi_gpio_1)                과제 (axi_gpio_0)
  ch1 = 입력 4 = sw4              ch1 = 출력 4 = led4
  ch2 = 출력 4 = led4             ch2 = 입력 4 = sw4
```

뒤바뀜이 **세 군데**로 번진다. 과제의 첫 번째 포인트("채널 번호는 방향이 정해져 있는 게 아니라 내가 설정하는 것")가 이 세 군데에서 드러난다.

| | 8장 | 과제 |
|---|---|---|
| IP 파라미터 | `C_ALL_INPUTS`(ch1) + `C_ALL_OUTPUTS_2`(ch2) | **`C_ALL_OUTPUTS`(ch1) + `C_ALL_INPUTS_2`(ch2)** |
| Make External 할 멤버 신호 | `gpio_io_i`(ch1) → `sw4`, `gpio2_io_o`(ch2) → `led4` | **`gpio_io_o`(ch1) → `led4`, `gpio2_io_i`(ch2) → `sw4`** |
| 레지스터 오프셋 | `sw4`=`+0x0`, `led4`=`+0x8` | **`led4`=`+0x0`, `sw4`=`+0x8`** |

**그런데 XDC는 바뀌지 않는다.** 채널이 바뀌면 *살아 있는 멤버 신호의 이름*이 바뀌지만(`gpio_io_i` → `gpio_io_o`), Make External 할 때 **우리가 붙이는 외부 포트 이름**은 여전히 `led4`·`sw4`다. XDC는 그 외부 포트 이름만 보므로 고칠 것이 없다. 과제 4번이 "왜 그런지 설명할 수 있어야 한다"고 묻는 것이 바로 이 구분이다 — **IP 내부의 신호 이름과 top 포트 이름은 다른 층위**라는 것.

## `build_homework_reference.tcl` 사용법

```
cd <이 LAB03 폴더>
vivado -mode batch -source build_homework_reference.tcl
```

**경로 주의.** 이 저장소는 `...\문서\GitHub\...` 처럼 한글이 섞인 경로에 있고 Vivado는 비ASCII·긴 경로에서 실패할 수 있다. 스크립트가 자기 경로의 비ASCII를 감지하면 **자동으로 `C:/vivado_w4`에 빌드**한다. 다른 위치를 쓰려면 `W4_BUILD_DIR` 환경변수를 지정한다.

쓰는 상황은 LAB01의 TCL과 같다.

1. **검증** — 이 설계가 Vivado 2023.2에서 합성·구현·XSA export까지 통과하는지 확인.
2. **채점** — 학생 프로젝트와 정상 설계를 비교.
3. **구제** — Vivado 부분에서 막힌 학생이 **소프트웨어 과제(`main.c` 작성)는 할 수 있게** 해 준다. 과제의 배울 거리는 대부분 소프트웨어 쪽에 있으므로, 하드웨어에서 막혀 전부 못 하는 것보다 낫다.

스크립트는 합성 전에 **top 포트 이름과 배정된 주소를 출력**한다. 포트가 `led4`·`sw4`로 접미사 없이 나와야 하고, 접미사(`led4_tri_o` 등)가 붙으면 멤버 신호가 아니라 인터페이스를 Make External 한 것이므로 XDC가 안 맞는다.

## 교수자용 — `main.c` 채점 기준

### 요구 동작 (과제 9번)

- `sw4`(채널 2)를 읽어 그 값을 `led4`(채널 1)로 출력, 무한 반복.
- `sw4`가 `0x0F`면 `exit`로 종료. `#include <stdlib.h>` 필요.

### 채널·방향·오프셋 정답

전체 코드는 [`src/main.c`](src/main.c)(드라이버)와 [`src/main_register_version.c`](src/main_register_version.c)(레지스터)에 있다. 요점만 표로.

| 항목 | 드라이버 방식 | 레지스터 방식 |
|---|---|---|
| `led4` 방향(출력) | `XGpio_SetDataDirection(&gpio, 1, 0x0)` | `Xil_Out32(base+0x4, 0x0)` |
| `sw4` 방향(입력) | `XGpio_SetDataDirection(&gpio, 2, 0xF)` | `Xil_Out32(base+0xC, 0xF)` |
| `sw4` 읽기 | `XGpio_DiscreteRead(&gpio, 2)` | `Xil_In32(base+0x8)` |
| `led4` 쓰기 | `XGpio_DiscreteWrite(&gpio, 1, v)` | `Xil_Out32(base+0x0, v)` |

`base`는 `XPAR_AXI_GPIO_0_BASEADDR`(= `0x4120_0000`).

정답 코드는 **LED를 쓴 다음에 종료 조건을 검사**한다. 그래야 종료 직전에 LED가 `0xF`를 한 번 표시하고, 그 값이 종료 후에도 남는다("확인해 볼 것" 참고). 순서를 바꾸면 `0xF`를 보지 못하고 끝나므로, 학생 코드의 순서와 학생이 적어 온 관찰이 일치하는지 보면 좋다. 둘 다 정답이며 관찰 내용이 코드와 맞으면 된다.

루프에 `usleep`을 넣지 않았다. 매 루프마다 출력하지 않으니 터미널이 넘칠 일이 없고, 지연이 없어 스위치 반응이 즉각적이다. 학생이 `usleep`을 넣었어도 무관하다.

### 중요 — 방향 설정은 **실행으로 채점할 수 없다**

이 설계는 두 채널을 `All Outputs`/`All Inputs`로 **고정**했으므로 방향이 합성 시점에 정해지고, `TRI` 레지스터를 쓰는 코드는 동작에 영향을 주지 않는다(9.3절 참고 — 래퍼 포트가 `output [3:0] led4`로 단방향인 것이 증거다). 따라서

- 방향 설정 두 줄을 **아예 빼도** 정상 동작한다.
- 방향 값을 **8장처럼 거꾸로 써도** 정상 동작한다.

즉 "확인해 볼 것" 첫 항목(방향 설정이 8장과 반대가 된다)은 **보드 동작으로는 맞았는지 알 수 없고, 코드를 읽어야 한다.** 채점할 때 이 점을 염두에 둘 것. 반대로 **읽기/쓰기 채널 번호는 틀리면 바로 드러난다** — 채널을 반대로 쓰면 LED가 아예 안 켜진다(엉뚱한 오프셋으로 가기 때문).

### 학생이 자주 틀리는 곳

| 실수 | 증상 |
|---|---|
| 8장 코드를 그대로 복사해 **채널 1에서 읽고 채널 2에 쓰기**(이 과제는 채널 2에서 읽고 채널 1에 쓴다) | LED가 전혀 안 켜지고, 읽은 값도 늘 `0`이다. 쓰기가 `+0x8`(입력 채널)로 가서 버려지고, 읽기가 `+0x0`(출력 채널)에서 오기 때문 |
| 인터페이스를 Make External (`led4_tri_o`가 됨) | 합성에서 `get_ports`에 이름이 없다는 경고, 핀 미배정 |
| `#include <stdlib.h>` 누락 | `exit` 암시적 선언 경고 또는 링크 오류 |
| `& 0xF` 마스크 누락 | 상위 비트 쓰레기값 때문에 `0x0F` 비교가 성립하지 않아 종료되지 않을 수 있다 |

### "확인해 볼 것"의 답

- **종료 후 LED는 어떤 상태로 남는가** — 마지막에 쓴 값(`0xF`, 전부 켜짐)이 **그대로 남는다.** `led4`는 AXI GPIO의 출력 레지스터가 직접 구동하는 단방향 출력이고, CPU가 멈춰도 그 레지스터 값은 지워지지 않는다. PS가 끝났는데 PL은 마지막 상태를 유지한다 — PS와 PL이 별개라는 것이 이 관찰로 드러난다.
- **스위치 4개를 모두 올린 채로 `Run`** — 첫 루프에서 곧바로 `0x0F`를 읽어 거의 즉시 종료한다. LED가 켜지는 것을 보기도 전에 끝날 수 있는데, 종료 조건을 LED 출력 **전에** 검사하는지 **후에** 검사하는지에 따라 관찰 결과가 달라진다. 학생 코드의 순서와 관찰 내용이 일치하는지 보면 좋다.

## 검증 필요

- **TCL 실행 확인.** `tclsh`로 Tcl 문법은 통과했으나 **Vivado에서 실제로 돌려보지 않았다.**
- **`C_ALL_OUTPUTS` / `C_ALL_INPUTS_2` 파라미터 이름**이 AXI GPIO 2.0에서 정확한지 확인한다(채널 1은 접미사 없음, 채널 2는 `_2`).
- **멤버 신호 이름.** ch1이 `All Outputs`일 때 `gpio_io_o`, ch2가 `All Inputs`일 때 `gpio2_io_i`로 나오는지 BD에서 확인한다. 이름이 다르면 `make_bd_pins_external` 두 줄을 고친다.
- **top 포트가 `led4`·`sw4`로 접미사 없이** 나오는지(스크립트가 출력한다).
- **주소가 `0x4120_0000`인지** — 다르면 위 채점 표의 `base`를 그에 맞춰 읽는다.
